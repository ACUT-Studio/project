# AGENTS.md

Інструкції для AI-агентів (Claude Code, Codex, Copilot тощо), які працюють у цьому репозиторії.

## Про проєкт

**AcutStudio**: настільна гра для Windows, що поєднує симулятор розвитку міста (будівлі, валюта, дерево навичок, завдання, крафтинг, біржа) і покрокові бої. Командний навчальний проєкт з дисципліни «Програмна інженерія. Частина 1».

Стек: C#, .NET 10, WPF (MVVM), SQLite через `Microsoft.Data.Sqlite` (ADO.NET, **без ORM**), `Microsoft.Extensions.DependencyInjection`, xUnit.

Мова документації, коментарів і повідомлень комітів у проєкті: **українська**. Ідентифікатори в коді: англійською.

## Структура рішення

| Проєкт       | Призначення                         | Target             |
|:-------------|:------------------------------------|:-------------------|
| `acut`       | WPF-застосунок (Views, ViewModels), composition root у `App.xaml.cs` | `net10.0-windows` |
| `Acut.Core`  | Ігрова логіка (Domain, Services, Abstractions) | `net10.0` |
| `Acut.Data`  | SQLite: схема, каталог, репозиторії, мапери | `net10.0` |
| `Acut.Tests` | Тести (xUnit)                       | `net10.0`          |

Рішення: `acut.slnx` (новий формат, потрібен свіжий .NET SDK).

## Команди

Потрібні Windows і .NET 10 SDK (WPF працює лише на Windows).

```
dotnet build acut.slnx
dotnet run --project acut
dotnet test acut.slnx
```

Перед завершенням завдання переконайся, що `dotnet build acut.slnx` проходить без помилок, а `dotnet test acut.slnx` зелений (коли тестовий проєкт існує). Якщо не можеш запустити команди (наприклад, не Windows), прямо скажи про це, а не стверджуй, що все працює.

Файл БД: `%LocalAppData%\AcutStudio\acut.db`, створюється автоматично. Щоб почати з нуля, його видаляють.

## Архітектурні правила (обов'язково)

**Напрямок залежностей: усе спрямоване до Core.**

```
acut ──► Acut.Core ◄── Acut.Data
   └────────────────────► Acut.Data   (лише для composition root)
Acut.Tests ──► Core, Data
```

1. `Acut.Core` **не посилається** на WPF, `Microsoft.Data.Sqlite` чи будь-що з `Acut.Data`/`acut`. Жодних `System.Windows.*`, `DispatcherTimer`, SQL у Core.
2. Інтерфейси `ISaveRepository` та `ICatalogRepository` **оголошені в Core** (`Abstractions/`), реалізовані в Data.
3. UI: **MVVM**. Логіка екрана живе у ViewModel (`INotifyPropertyChanged`, `ICommand`), у code-behind лише суто візуальне. ViewModel викликає Core, а не Data напряму.
4. Залежності збираються в одному місці: `App.xaml.cs` (DI). Не використовуй service locator і статичні синглтони для сервісів.
5. Тіки симуляції запускає UI (`DispatcherTimer` викликає `City.Tick()`). Таймерів усередині Core немає: так логіку можна тестувати, викликаючи `Tick()` вручну. У стані «Пауза» таймер зупиняється.
6. Доменна модель з поведінкою: правила й інваріанти живуть у доменних класах (`Player`, `Battle`, `City` тощо), наприклад, здоров'я в межах `0..MaxHealth`. Не виноси їх у «сервіси на все».
7. Завдання, досягнення й статистика реагують на **події** через `GameEventDispatcher` (`GameEvent`). Не додавай прямих викликів із джерел подій (місто, бій, крафтинг) до `QuestLog`/`AchievementTracker`/`PlayerStatistics`.
8. Поведінка ворогів: Strategy (`IEnemyStrategy`). Нова поведінка = новий клас + значення `StrategyType` у каталозі. **Не** додавай розгалужень за типом ворога в `Battle`.
9. Нові типи будівель, предметів, персонажів додавай наслідуванням, не змінюючи наявний код без потреби.

## Дані та SQLite

- Доступ до даних: **ADO.NET без ORM**. Не додавай EF Core, Dapper чи інші ORM: це прямо суперечить вимогам курсу.
- Ігровий контент (будівлі, предмети, вороги, навички, завдання, досягнення, акції, рецепти) задається **каталогом у БД** (`Acut.Data/Sql/seed.sql`), а не константами в коді. Баланс і нові сутності додавай рядками в `seed.sql`.
- Схема: `Acut.Data/Sql/schema.sql`. Обидва скрипти є вбудованими ресурсами.
- Версія схеми зберігається в `PRAGMA user_version`; зміна схеми потребує міграції, яку `DatabaseInitializer` застосовує по черзі. Не перезаписуй стару схему мовчки.
- Зовнішні ключі увімкнені (`PRAGMA foreign_keys = ON` у `SqliteConnectionFactory`). Зберігай `CHECK`-обмеження (`Gold >= 0`, `Level >= 1`, `Health BETWEEN 0 AND MaxHealth`).
- Конвенції типів: `Guid` як `TEXT`; дата й час як `TEXT` у ISO 8601; `enum` як `TEXT` з `CHECK`; гроші й ціни акцій як цілі числа (акції в сотих частках), **не `REAL`**.
- Каталог і стан гри розділені. Стан прив'язаний до `GameSave` з каскадним видаленням. `BuildingStatus` `Locked`/`Available` не зберігається, а обчислюється за навичками гравця.
- **Збереження гри виконується однією транзакцією** (`BEGIN` → UPSERT усіх таблиць стану → `COMMIT`, при помилці `ROLLBACK`). Не розбивай збереження на кілька незалежних транзакцій. Активний бій (`ActiveBattle`) теж зберігається.
- Усі SQL-запити параметризовані. Ніколи не конструюй SQL конкатенацією рядків із введенням користувача.

## Стиль коду

- C# з `nullable` та сучасним синтаксисом .NET 10. Дотримуйся `.editorconfig`, якщо він з'явиться, і стилю сусідніх файлів.
- Назви класів, методів і таблиць мають збігатися з `Architecture.md` та UML-діаграмами. Якщо потрібне відхилення, онови документ у тому ж змінюванні.
- Роби мінімальні, цілеспрямовані зміни. Не рефакторь і не форматуй код, який не стосується завдання.
- Не додавай нових NuGet-пакетів без потреби. Якщо додаєш, поясни навіщо в описі PR.
- Не блокуй UI-потік довгими операціями.

## Тестування

- Фреймворк: **xUnit**, проєкт `Acut.Tests`.
- Критичну логіку Core (бій, економіка міста, інвентар, крафтинг, навички, завдання) тестуй **без** WPF і БД: підставляй заглушки замість репозиторіїв.
- `Acut.Data` перевіряй інтеграційними тестами на SQLite **у пам'яті**, а не на реальному файлі користувача.
- Нова поведінка або виправлена помилка = тест. Не видаляй і не послаблюй наявні тести, щоб «позеленіти».

## Git і PR

- Основна гілка: `main`. Працюй у окремій гілці та відкривай PR, а не пуш напряму в `main` (етап 6 передбачає гілки й перегляд коду).
- Повідомлення комітів: українською, стисло, в наказовому способі, одна зміна на коміт.
- CI: GitHub Actions (збирання й запуск тестів, етап 8). PR не вважається готовим, поки збірка й тести не проходять.
- Не коміть `bin/`, `obj/`, `.vs/`, файли `*.db`, локальні налаштування IDE. Перевір `.gitignore`.

## Чого не робити

- Не порушувати напрямок залежностей (див. «Архітектурні правила»).
- Не переходити з ADO.NET на ORM і не замінювати SQLite іншою БД.
- Не хардкодити ігровий контент і баланс у коді замість `seed.sql`.
- Не вводити WPF-типи в `Acut.Core`.
- Не читати, не змінювати й не видаляти `%LocalAppData%\AcutStudio\acut.db` без прямої вказівки.
- Не вигадувати фічі поза вимогами: звіряйся з `Requirements_Document.md` і `Tasks_Stage5-6.md`.
- Не виконувати етапи, що виходять за поточний (логування, валідація, перевірка безпеки належать до етапу 9), доки про це не просили.

## Коли не впевнений

Якщо вимоги суперечать одна одній або документація відстала від коду, **запитай** або чітко познач припущення в описі змін. Краще коротке уточнення, ніж тиха зміна архітектури.
